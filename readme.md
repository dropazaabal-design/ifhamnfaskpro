# Matjar Pro

قالب ووكومرس عربي، **RTL أصلي** لا معرَّب، مبني للتحويل على الجوال.
Tailwind CSS للتنسيق و Vanilla JavaScript للتفاعل، بلا jQuery في كود القالب.

- **الحد الأدنى:** PHP 8.0 · WordPress 6.4 · WooCommerce 8.0
- **معرّف الترجمة:** `matjar-pro`
- **العملة:** لا عملة مثبّتة في الكود. كل سعر يمرّ عبر `wc_price()` فيتبع
  عملة التاجر وموضع رمزها وفواصلها.

## حالة البناء

| المرحلة | المحتوى | الحالة |
|---|---|---|
| الأولى | تحليل UX/UI ولوحة الألوان والهياكل | مكتملة |
| الثانية | بيئة القالب، Tailwind، الخطوط، دعومات ووكومرس | مكتملة |
| الثالثة | الهيدر، الفوتر، الهيرو، الألواح، البحث الفوري | مكتملة |

| الخامسة | الفلترة، صفحة الحساب، الترجمة، التغليف | **هذه** |

## التركيب

```
functions.php          إقلاع وتعريف الثوابت
inc/
  helpers.php          العملة، حساب التباين، الأيقونات، الافتراضيات المركزية
  tokens.php           لوحات الألوان والخطوط ومخرجات متغيّرات CSS
  setup.php            add_theme_support ودعومات ووكومرس والقوائم
  assets.php           تحميل الأصول، CSS الحرج، إلغاء ما لا نستخدمه
  customizer.php       لوحة إعدادات التاجر
  woocommerce.php      الطبقة الهيكلية لووكومرس (تُحمَّل عند تفعيله فقط)
  wc-loop.php          بطاقة المنتج والشبكة وترتيب السعر
  wc-product.php       ترتيب صفحة المنتج السلوكي وعيّنات الخيارات
  wc-checkout.php      حقول الدفع والقُمع وتقدّم الشحن
  wc-filter.php        الفلترة بمتغيّرات ووكومرس الأصلية
  wc-account.php       صفحة الحساب وتقدّم الطلب
src/css, src/js        المصدر — يُبنى إلى assets/
assets/                المخرجات، وتُلتزم في المستودع عن قصد
template-parts/        الهيرو، شريط الثقة، الألواح، أجزاء المنتج والسلة والفلترة
woocommerce/           تجاوزات قوالب ووكومرس (البطاقة، المنتج، السلة، الدفع)
tools/                 نسخ الخطوط، فحص التباين، تصيير القوالب
```

## البناء

```bash
npm install
npm run build      # الخطوط + CSS + JS
npm run dev        # مراقبة مستمرة أثناء التطوير
npm run verify     # فحص التباين + تصيير القوالب
```

`assets/` **مُلتزمة في المستودع عن قصد**: التاجر المشتري لا يشغّل npm،
فالقالب يعمل كما هو بمجرّد التفعيل.

## القرارات الهندسية

### الألوان: مصدر واحد، وتباين مضمون بالحساب

كل لون يعيش في `inc/tokens.php` ويصل إلى المتصفح كمتغيّر CSS بصيغة قنوات
RGB (`--mp-cta: 194 65 12`) تُطبع في `<head>`. هذه الصيغة وحدها هي التي
تُبقي مُعدِّلات الشفافية في Tailwind (`bg-cta/10`) عاملة فوق المتغيّرات.

اللوحات الأربع المشحونة كلّها باردة رصينة، ولا لون دافئ في أي رمز علامة —
لا برتقالي ولا أصفر ولا ذهبي ولا بنّي. المساحة البصرية تُترك لصور المنتجات:

| اللوحة | الاستخدام | زر الشراء |
|---|---|---|
| `navy` | الافتراضي — فخم ونظيف | كحلي عميق `#173F73` على أبيض نقي |
| `emerald` | أزياء وطبيعي | أخضر زمردي `#046B4E` على أبيض نظيف |
| `mono` | إلكترونيات | أسود مائل `#14181D` مع أزرق تقني للإبراز |
| `carbon` | متجر داكن | أبيض `#FFFFFF` على أسود كربوني، ونصّه يُحسَب غامقاً |

الرموز تُسمّى بأدوارها لا بألوانها: `progress` لا `amber`، و`page` لا
`cream`، و`inverse` للسطح المعكوس الغامق دائماً — مستقلّاً عن `ink` لأن
الحبر في اللوحة الكربونية لونٌ فاتح. و`field` حدّ الحقول وحده يعبر ٣:١
لأنه وحده يُعلِم الزائر أين يكتب، بخلاف الحدّ الزخرفي بين الكتل.

التاجر يختار أربعة ألوان في أداة التخصيص — لون العلامة، ولون زر الشراء،
ولون خلفية الصفحات، ولون الإبراز — ويُشتَقّ منها ما بقي: لون العناوين
والنص والنص الباهت والحدود والأسطح. ولا يُعتمد أي لون كما جاء:

| الدالة | ما تضمنه |
|---|---|
| `matjar_pro_ensure_contrast()` | تدفع اللون في الاتجاهين — نحو العتمة ونحو الفتح — وتأخذ أوّل قيمة تعبر الحدّ بأقلّ تغيير. تجريب الاتجاهين ضروري: الخلفيات متوسطة السطوع لا يعبر عليها التفتيح ويعبر عليها التعتيم |
| `matjar_pro_usable_ground()` | تدفع لون الخلفية نفسه إن كان لا يحمل نصّاً. `#5E71B3` مثلاً أقصى تباين عليه ٤٫٤٩ بالأسود و٤٫٦٨ بالأبيض، وسطحه المشتَقّ يعكس الترتيب، فلا يوجد لون نصّ واحد يعبر على الاثنين — المسألة حسابية لا خطأ في الحساب |
| `matjar_pro_ensure_contrast_on_tint()` | الكتل الملوّنة تُبنى بلونٍ فوق طبقة من اللون نفسه بشفافية ٠٫٠٨، فالخلفية تتحرّك مع اللون. تُحسَب من المُرشَّح في كل خطوة بدل تثبيتها |
| `matjar_pro_readable_foreground()` | لون نص الزر: الأبيض أو الحبر، أعلاهما تبايناً |

و`npm run verify:colors` يجرّب ٤٠٠٠ تركيبة لون عشوائية (٨٤ ألف زوج) ويفشل
عند أوّل زوج تحت الحدّ. هذا الفحص هو ما كشف أن الاتجاه الواحد والطبقات
الشفّافة والخلفيات الميّتة ثلاث ثغرات حقيقية، لا فرضيات.

### الفحوص المؤتمتة

| الأمر | ما يفحصه |
|---|---|
| `npm run verify:contrast` | ٩٦ زوج لون/خلفية في اللوحات الأربع مقابل حدود WCAG 2.1، ويفشل عند أي إخفاق |
| `npm run verify:colors` | ٤٠٠٠ تركيبة ألوان تاجر عشوائية × ٢١ زوجاً، للتحقّق أن حرية الاختيار لا تُنتج نصّاً غير مقروء |
| `npm run verify:settings` | أن كل إعداد في أداة التخصيص له مُنقّي موجود وافتراضي معرَّف، وأن لا افتراضي بلا تحكّم (كود ميت) |
| `npm run smoke` | يُصيّر القوالب فعلاً مقابل مُحاكٍ خفيف لووردبريس وووكومرس، في سبعة مسارات: بلا ووكومرس، ومعه، وبتخطيط overlay، وبطاقة المنتج (بسيط وذو متغيّرات)، وقُمع الدفع، والفلترة بفلاتر مُفعَّلة، وصفحة الحساب. يحوّل كل تحذير إلى استثناء، فيكشف المتغيّرات غير المعرَّفة وفروع الشروط التي لا يراها `php -l` |
| `npm run preview` | يبني معاينة HTML قابلة للفتح في متصفح بلا تنصيب ووردبريس |
| `npm run pot` | يولّد ملف الترجمة بـ `token_get_all` — تحليل نحوي لا تعبيرات نمطية — ويفشل عند أي سلسلة غير حرفية أو بمعرّف ترجمة خاطئ |

المُحاكي ليس بديلاً عن تشغيل القالب على موقع حقيقي، لكنه يمنع صنف
الأخطاء الذي يُكتشف عادةً على شاشة بيضاء.

### أداة التخصيص: كل الإعدادات في لوحة واحدة

لا لوحة تحكّم خاصّة ولا إضافة: الإعدادات كلّها في Customizer API، فتُحمَّل
مع ووردبريس ولا تُضيف سطراً واحداً إلى الواجهة. شعار ووردبريس الأساسي
واسم المتجر يُنقَلان إلى اللوحة نفسها بدل تكرارهما، فتبقى آلية ووردبريس
للصور عاملة (أحجام الصور و`srcset`) ويجد التاجر كل شيء في موضع واحد.

| القسم | ما فيه |
|---|---|
| هوية المتجر | الشعار واسم المتجر |
| الألوان والخط | اللوحة الجاهزة، أربعة ألوان مخصّصة، الخط (Cairo أو IBM Plex Sans Arabic) |
| شارات الثقة وطرق الدفع | تفعيل كل وسيلة بدورها، صورة شارات التاجر، إبراز الدفع عند الاستلام، سطر شرحه، ضمانات الإرجاع والأمان |
| روابط التواصل | إنستغرام وتيك توك وسناب شات وإكس ويوتيوب — يُطبع ما عُبِّئ فقط |
| بيانات المتجر | السجل التجاري والرقم الضريبي وواتساب وحدّ الشحن المجاني |

**شعارات وسائل الدفع لا تُشحن مع القالب.** ملكيّتها لأصحابها، وشحنها في
قالب يُباع مسألة ترخيص لا تصميم. الشارات نصّية بألوان أدوار، والتاجر يرفع
صورة الشعارات الرسمية من مزوّد الدفع في `صورة شارات الدفع` فتظهر بدلها.

### RTL: خصائص منطقية لا ملف معاكس

لا إضافة `rtl` ولا `rtl.css`. التنسيق يستخدم خصائص Tailwind المنطقية
(`ps/pe`، `ms/me`، `start/end`)، و`float` و`clear` **مُعطَّلان** في
`tailwind.config.js` لأنهما أكبر مصدر لأخطاء الاتجاه. الأرقام والأسعار
تُعزل بـ `.mp-num` (اتجاه LTR داخل نص RTL) وإلا تشقلبت الأرقام والفواصل.

### الخطوط: عائلتان مرفقتان، واحدة تُحمَّل

| العائلة | النوع | الحجم على الزائر |
|---|---|---|
| **Cairo** (الافتراضي) | متغيّر، كل الأوزان | **63.2 KB / ملفان** |
| IBM Plex Sans Arabic | ساكن، 3 أوزان × نطاقان | 187 KB / 6 ملفات |

كلتاهما مستضافة ذاتياً — **لا اتصال بأي خدمة خطوط خارجية** — ويُحمَّل على
الزائر ملفات المختارة فقط، مع `unicode-range` يمنع تنزيل الحروف اللاتينية
على صفحة عربية خالصة، و`preload` لما يُرسم فوق الطيّة.

### التباين فوق الصور

النص الأبيض على صورة يرفعها التاجر لا يمكن ضمان تباينه بالتصميم، فيُضمن
بالحساب. التخطيط الافتراضي للهيرو «الصورة ثم النص» لا يضع نصاً فوق صورة
إطلاقاً. وتخطيط «النص فوق الصورة» يفرض طبقة كحلية بشفافية **65%**، وهي
أدنى قيمة تعطي 5.25:1 فوق صورة بيضاء ناصعة — أسوأ حالة ممكنة. الشفافية
60% تعطي 4.47:1 وترسب بفارق ضئيل، فلم تُستخدم.

### ترتيب صفحة المنتج

الترتيب سلوكي لا إداري: كل عنصر يُزيل اعتراضاً قبل أن يصل الزائر إلى الزر.

```
الاسم ← التقييم ← السعر والتوفير ← التقسيط ← الخيارات
     ← الكمية وزر الشراء ← شارات الثقة ← موعد التوصيل
     ← المخزون ← نقاط المنفعة ← الأكورديون ← التقييمات
```

شارات الثقة وموعد التوصيل **بعد** الزر لا قبله: لحظة التردد تأتي بعد رؤية
الزر. والتقسيط **قبله**: اعتراض السعر يجب أن يُحلّ قبل لحظة القرار.

السعر الجديد يُخرَج قبل القديم: ووكومرس يُخرج `<del>` ثم `<ins>`، أي أن
العين في RTL تقرأ السعر القديم أولاً فيضعف أثر الخصم. النسختان المرئيتان
مخفيّتان عن قارئ الشاشة، ومعهما جملة صريحة بدلاً منهما.

### منطق المتغيّرات و jQuery

القالب خالٍ من jQuery. الاستثناء الوحيد أن **ووكومرس** يُحمّل سكربته
الخاص للمتغيّرات (`wc-add-to-cart-variation`) في صفحات المنتج ذي
المتغيّرات، وهو مبني على jQuery.

القرار: لا نُعيد كتابته. نبني أزرار الخيارات المرئية فوق حقول `select`
التي يقرأها ووكومرس، ونُطلق حدث `change` أصلياً — ومعالجات jQuery تستجيب
للأحداث الأصلية. النتيجة: واجهة أزرار مرئية بمنطق مُجرَّب، بدل إعادة
كتابة تسعير المتغيّرات ومخزونها وصورها من الصفر.

الحقل المنسدل يبقى عاملاً عند تعطيل JavaScript.

### الفلترة

تعتمد على **متغيّرات استعلام ووكومرس الأصلية** (`filter_pa_*` و`min_price`
و`max_price`)، وهي من نواة ووكومرس لا من إضافة: `WC_Query` يقرؤها ويطبّقها
بنفسه. لا مكتبة فلترة، ولا نقطة نهاية مخصّصة.

- كل خيار **رابط GET** وفلتر السعر **نموذج GET**: الفلترة تعمل كاملة بلا
  JavaScript، وطبقة AJAX تُحسّنها ولا تشترطها.
- AJAX لا يبني نتائج في المتصفح: يطلب الصفحة نفسها بالرابط الجديد ويستبدل
  منطقة النتائج وأجزاء الفلترة. التصيير يبقى على الخادم، فالرابط الذي يراه
  الزائر هو الرابط الذي يمكن أن يشاركه، ويعمل زر «رجوع».
- أي فشل شبكة يعود إلى الانتقال الكامل للرابط.
- شريط السعر بمقبضين بلا مكتبة: حقلا `range` متراكبان، الأحداث معطّلة على
  الحقل ومفعّلة على مقبضه وحده. الملء يُحسب بخصائص منطقية
  (`inset-inline-start` و`inline-size`)، فينقلب مع اتجاه الصفحة تلقائياً.
- حدّا السعر يُقرآن من `wc_product_meta_lookup` ويُخزّنان 12 ساعة، ويُفرَّغان
  عند تغيّر سعر أي منتج.

### صفحة الحساب

المشتري لا يريد لوحة تحكم، يريد جوابين: «أين طلبي؟» و«هل عنواني صحيح؟».
الصفحة مرتّبة حول هذين السؤالين: الطلب الجاري أولاً وبأكبر مساحة، ثم
العنوان، ثم روابط قصيرة.

الطلبات **بطاقات لا جدول** — جدول ووكومرس بستة أعمدة ينكسر في 390 بكسل.
وشريط تقدّم الطلب **ثلاث خطوات لا أكثر**: ووكومرس لا يملك حالة «تم الشحن»
في نواته، وخطوة لا تقابلها حالة حقيقية تعني شريط تقدّم يكذب. الحالات
النهائية غير الناجحة تُعرض كحالة صريحة لا كتقدّم. التصفية
`matjar_pro_order_progress` تسمح للتاجر بإضافة حالته المخصّصة.

### حزم JavaScript مجزّأة

| الحزمة | تُحمَّل في | الحجم مضغوطاً |
|---|---|---|
| `main.js` | كل الصفحات | ~3.5 KB |
| `shop.js` | الأرشيف والبحث | ~1.4 KB |
| `product.js` | صفحات المنتج | ~1.4 KB |
| `checkout.js` | السلة والدفع | ~0.9 KB |

الصفحة الأولى لا تحمل كود المعرّض ولا الفلترة، وصفحة المنتج لا تحمل كود
التحقّق من حقول الدفع.

### منع انزياح التخطيط (CLS)

- كل صورة منتج داخل نسبة **4:5** مفروضة في التنسيق، ومعها `width` و
  `height` في الوسم: المتصفح يحجز المساحة قبل وصول الصورة، وصورة رفعها
  التاجر بنسبة مختلفة لا تكسر الشبكة.
- مقاس `matjar-pro-card` مقصوص بالقوة على 400×500.
- الأشرطة الثابتة تظهر وتختفي بـ `transform` لا بتغيير الارتفاع.
- زر الإضافة السريعة يغيّر حالته داخل مقاس ثابت 44×44.

### transform والاتجاه

موضعان في القالب يحتاجان تجاوزاً صريحاً للاتجاه: انزياح اللوح الجانبي
ولوح السلة. `transform` لا يملك نسخة منطقية في CSS — `translateX(-100%)`
يزيح يساراً دائماً — واللوحان مثبّتان على جهتي بداية السطر ونهايته. لذلك
`[dir='rtl']` يقلب متغيّر الانزياح لكلٍّ منهما. ما عدا ذلك لا تجاوز اتجاه
في القالب.

**الأيقونات الاتجاهية** مكتوبة أصلاً باتجاه العربية: `arrow` يشير يساراً
(إلى الأمام) و`back` يشير يميناً (إلى الخلف). لذلك **لا تُقلب** بأداة
`.mp-flip`، وهي محفوظة لأيقونة خارجية مكتوبة لاتينياً.

### الأداء

- تنسيقات ووكومرس الثلاث مُلغاة والقالب يبني تنسيق المتجر كاملاً.
- `@font-face` ومتغيّرات الألوان مضمّنة في الترويسة: طلب شبكة أقل، وبلا
  وميض ألوان افتراضية.
- السلة عبر **Store API** لا `admin-ajax`.
- أولوية تحميل الصور متروكة لمُحسِّن ووردبريس المدمج (6.3+)، وهو أدقّ من
  أي استدلال يدوي على «أول صورة في الصفحة».
